## Ownership, compatibility and preservation audit

Child senders capture the complete active child identity (incarnation, parent registration/session/name and parent owner) and local source namespace. Child-origin receipt inspection requires an explicit current child selector authenticated through `NativeChildren.own`; unscoped parent, other child, foreign parent, stopped child and recreated child cannot borrow it. A real paired-host regression deliberately collides parent registration/session IDs and checks the authenticated receipt wire cannot borrow the local child source. Child return, dedupe and recipient ACK guards remain unchanged. Historical rows missing original sender evidence remain retained and fail closed.

Session learning waits only on the node's existing in-flight registration. It does not accept a mismatched attestation, infer a different session from a name or start a provider. Legitimate same-session reload and distinct-session exclusion remain tested.

Atomic admission is restricted to new, proven, local job-supervisor reports. Its synchronous storage boundary revalidates the original registration after any write retry, then stores the request, typed local grant, body/UUID, namespace and generation-zero copy in one transaction. A SQLite failure rolls all new evidence back and preserves previously accepted unrelated mail and proofs. There is no external dispatch before that boundary. A successfully admitted copy uses the existing immutable grant/succession/ACK machinery. Ordinary exact-name sends, concretely claimed role copies and pinned remote sends retain their prior fences; a local job admission cannot dispatch remotely. Existing request-only orphan intents are not deleted, guessed or automatically recovered. Their retained runner result and intent need owner-safe reviewed recovery if storage never occurred.

No schema, local protocol, pairing or remote capability change: schema14/protocol6 and all three remote ownership capabilities remain. The optional child receipt selector adds a scoped query; it cannot mint sender ownership or grant a parent implicit child authority. Existing intermediate brokers reject child-origin receipt queries against their parent-only proof check; no fallback is added. All intermediate protocol/schema versions remain unreleased branch states.
